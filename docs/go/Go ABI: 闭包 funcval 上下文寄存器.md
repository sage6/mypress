# Go ABI：闭包 funcval、上下文寄存器，完整理解

> 线头承接前面：普通函数参数、寄存器传参、spill space；现在轮到**闭包调用**。

## 先回顾底层结构体（runtime源码）

```
// runtime/runtime2.go
type funcval struct {
    fn uintptr // 真正要执行的函数入口地址
    // 后面紧跟的内存：捕获变量的环境数据，闭包对象
}
```

- `funcval` 就是**闭包对象**。它在堆上分配（大部分情况）。
- `fn`：闭包对应的机器码函数地址。
- fn后面连续内存：存放所有被捕获的外部变量。

> ⚠️重点：闭包对应的**真正执行的函数，并不是直接拿到捕获变量**！
> 这个生成的闭包函数，它的参数列表**不会把捕获变量写进Go源码的参数**。捕获变量不在普通参数里。

举例子源码：

```
func outer() func(int)int{
    v := 100
    return func(x int) int {
        return v + x // v 是捕获的外部变量
    }
}
```

编译器内部会生成一个**底层闭包函数**伪代码：

```
// 编译器生成的隐藏函数，源码看不到
func closureFunc( *funcval, x int ) int {
    env := (*funcval)(ctx)
    v := env[0] // 从funcval环境里取出捕获变量v
    return v + x
}
```

> 用户写的函数签名：`func(x int)int`
> **真实ABI底层签名多出来第一个隐藏参数：`ctx *funcval`**

## ABI专门的闭包上下文寄存器（amd64 Go ABI）

普通函数：参数依次分配整数寄存器、浮点寄存器，满了落栈。
**闭包调用有特殊约定：有一个寄存器专门传递这个 funcval 指针（闭包环境指针）。**

> 在 amd64 Go ABI：闭包上下文 `ctx`，固定用 **BX寄存器** 传递。

### 调用闭包全过程拆解

```
f := outer()   // f 是 *funcval 闭包对象指针
res := f(5)    // 调用闭包，传入实参x=5
```

1. `f` 是 `*funcval` 指针，指向堆上的 `funcval` 结构体
2. **调用方执行闭包调用前：把 `f`（funcval指针）放进 BX 寄存器（闭包上下文寄存器）**✅
3. 普通实参 `x=5`，按照普通ABI规则，走正常参数寄存器/栈
4. 执行 call 跳转到 `funcval.fn`（闭包机器码入口）
5. **被调用的闭包函数，首先读 BX 寄存器，拿到 funcval 指针**
6. 通过这个指针，访问 funcval 后面保存的全部捕获变量。

```
调用方
    f *funcval ------> [ funcval{ fn:闭包函数地址; 捕获变量v } ]
        │
        ├─ mov BX, f      ✨【ABI约定】BX固定携带闭包上下文指针
        └─ 把普通参数x=5放到对应参数寄存器
        call [f.fn]

被调用闭包函数开始执行：
    第一步：读取 BX，得到funcval的指针
    从BX指向的内存取出捕获变量v
    再拿普通参数x，执行 v + x
```

## 关键问题：为什么不能把捕获变量当作普通函数参数？

1. **闭包是第一类对象**：`f` 可以到处传、存变量、放到slice、返回出去。调用点是动态的，编译器编译时不知道会在哪里调用闭包。
2. 捕获的变量数量不固定：不同闭包捕获变量数量不一样。如果作为普通参数，每次调用要堆一堆参数，无法统一。
3. `funcval` 是一个**统一的闭包句柄**。不管捕获多少变量，对外只暴露一个指针。调用闭包时，只需要把这一个指针送入专用上下文寄存器。普通参数照常走原来ABI。

> 普通函数没有闭包环境，BX就不承担上下文角色；**只有调用闭包的时候，BX被用作闭包ctx寄存器**。

## 和前面循环goroutine闭包陷阱串联（接上最开始的线头）

```
for _,v := range []int{1,2,3}{
    v:=v
    go func(){ fmt.Println(v) }()
}
```

1. 每轮迭代`v:=v`生成新变量。编译器生成闭包，在堆上分配`funcval`。`funcval`环境里面存本轮v的拷贝/指针。
2. `go` 启动goroutine，把这个`*funcval`交给runtime。
3. goroutine调度执行闭包的时候：**把funcval指针载入BX寄存器**，闭包函数从BX拿到捕获的v。

- Go1.21没有`v:=v`的时候：所有闭包的`funcval`环境里面，存的是**同一个外层循环变量&v**；全部通过BX拿到同一个地址，读到末尾值。
- `v:=v`后，每个闭包funcval环境保存各自独立变量地址，BX取出来就是各自的v。

## 区分两个东西，极易混淆

1. **BX寄存器的值：`*funcval`指针（闭包对象指针）**
   - 不是直接存捕获变量；存的是指向funcval结构体的指针。
   - funcval结构体后面的内存区域，才存捕获变量。
2. 普通函数参数：走通用参数寄存器，和BX无关。

## 结合ABI的spill空间（你上一张流程图）

BX保存的是闭包上下文指针（寄存器）。

> 如果发生GC安全点、栈扩容：寄存器中的BX（funcval指针）同样需要spill溢出，写到栈上spill space，防止寄存器的值被覆盖，GC也能扫描到这个闭包指针。

## 一句话总结

> Go ABI给闭包专门约定了一个上下文寄存器（amd64下BX）。调用闭包之前，调用方把`funcval`（闭包对象）的指针放到这个寄存器；被调用的闭包函数上来就读这个寄存器，拿到环境指针，才能访问所有捕获的外部变量。普通函数不走这套逻辑。
